Security — Default Values Everywhere for Jira

Publisher: Klix (Anthony Laude) · Security contact: support@klix.nc · Updated 2026-09-29

Architecture

  • Built on Atlassian Forge and eligible for Runs on Atlassian: no remote backend, no external egress, no servers operated by the publisher.
  • Data (default-value rules and a 30-day activity log) is stored only in Forge-hosted storage, encrypted at rest by Atlassian, in the customer site's data residency location.
  • The publisher has no access to customer data. The app never asks for passwords, API tokens or other credentials.

Secure development

  • Least-privilege scopes, each justified in the listing.
  • Server-side authorization: every admin request is checked against the caller's Jira administrator permission before any write.
  • Server-side validation of all rule input (shape, types, sizes).
  • Before every commit: unit tests, strict type checks, manifest validation against the Forge schema, and verification of every REST call against Atlassian's official OpenAPI specifications. Changes are tested on a development site before production.
  • Dependencies are kept minimal (Atlassian Forge SDK) and scanned with npm audit before each release.
  • Logs contain only work item keys, field IDs and status codes: no personal data, credentials or tokens.
  • Publisher workstation: supported operating system with automatic updates and real-time endpoint protection.

Vulnerability remediation

We follow the Atlassian Marketplace Security Bug Fix Policy:

Severity Fixed within
Critical (CVSS ≥ 9.0) 10 days
High (≥ 7.0) 4 weeks
Medium (≥ 4.0) 12 weeks
Low (< 4.0) 25 weeks

Incident response

  1. Contain: disable the affected feature or roll back to the previous version (Forge deployment rollback).
  2. Notify Atlassian with a P1 ticket in the Marketplace Partner service desk within 24 hours of discovery, with scope, impact on end-user data, containment, and estimated resolution; update Atlassian at least every 6 hours during remediation.
  3. Notify affected customers within 72 hours, using Atlassian's communication templates.
  4. Fix, verify, deploy, then publish a root-cause analysis and preventive actions.

Reporting a vulnerability

Email support@klix.nc with "SECURITY" in the subject. We acknowledge within 1 business day.
